# Learning journal 2026-11-18

### 2026-11-18: Configuration and authentication — Kernel applies case variants of client-only conf keys in sorted order, so the lowercase key wins
**Context:** In PR #566 the review bot raised the same finding twice: leaving an uppercase `CLOUDFETCH_MAX_CHUNKS_IN_MEMORY` next to the canonical lowercase key would let Go map iteration order pick the winner. Both times the maintainer cited the pinned kernel `session.rs`. It runs `sort_unstable()` over the recognized case variants, applies them in byte order (so all-lowercase comes last), then strips them all before the request reaches the server.
**Rule:** Before flagging map-iteration nondeterminism for case-variant kernel client-only session-conf keys, check the pinned kernel's sorted case-variant application, where the canonical lowercase key written by a typed option always wins.

### 2026-11-18: Configuration and authentication — Use a Set flag when a Go config field is pre-filled with its default
**Context:** In PR #566 `MaxDownloadThreads` defaults to 10 even when omitted. The PR added `MaxDownloadThreadsSet`, set by both the option and the DSN parser and carried through DeepCopy, so the kernel keeps its own default of 16 when the value is unset but honors an explicit 10.
**Rule:** When a Go config field is pre-populated with a Thrift default and is now forwarded to a backend with a different default, add an explicit Set flag in every entry point and in DeepCopy so that unset and explicitly-set-to-default can be told apart.

### 2026-11-18: Verification and dependencies — Forwarding a formerly inert option to a new backend is a behavior change
**Context:** In PR #566 `maxDownloadThreads` used to do nothing on the kernel and now controls the kernel chunk window. A reviewer pointed out that existing DSNs tuned for Thrift (for example 64) now change kernel memory use and throughput, and the CHANGELOG entry was relabeled `**Behavior change:**`. The same reviewer also noted that the new presence test only had cases where the value was unset, so the forwarding path was never exercised.
**Rule:** When an option that used to be inert on a backend starts being forwarded to it, label the CHANGELOG entry as a behavior change, describe how existing tuned values now affect that backend, and add test cases where the value is set, not only cases where it is unset.
