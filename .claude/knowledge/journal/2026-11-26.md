# Learning journal 2026-11-26

### 2026-11-26: Native boundaries and lifecycle — Pinned sql.Conn bypasses pool validation; reject dead sessions locally before sending
**Context:** PR #595 evicted kernel sessions on SEA 'Session does not exist' or 'Invalid SessionHandle' errors. A conn pinned with db.Conn never goes back through IsValid, so the next Exec or Query still reached the server. The fix makes Execute return ErrBadConn before submitting anything, while the failing statement's own error stays non-ErrBadConn so database/sql does not replay it.
**Rule:** When marking a session dead, keep the failing statement's error free of driver.ErrBadConn to prevent replay, and have the next Execute return ErrBadConn locally before sending anything, because pinned sql.Conn instances skip driver.Validator.

### 2026-11-26: Native boundaries and lifecycle — Keep definite session loss separate from transient eviction signals
**Context:** In PR #595 the reviewer found that one valid flag served both cases. It was set by transient Unavailable, NetworkError and Unauthenticated errors as well as by definite session-missing errors. A pinned conn whose server session was still alive then returned ErrBadConn forever, which the CHANGELOG did not describe.
**Rule:** Use a separate state flag for definite server-side session loss when it permanently rejects later requests, or document and test the wider behavior for transient codes that share the eviction path.

### 2026-11-26: Configuration and authentication — Match session-fatal errors on code plus message, with negative cases
**Context:** In PR #595, SEA reports an expired session as NotFound and a bad handle as InvalidArgument. Those same codes also cover missing tables, missing statements and bad parameters. Classification was narrowed with case-insensitive message substrings, and tests cover SQL errors that echo the same text.
**Rule:** When a generic status code like NotFound or InvalidArgument signals session loss only in some cases, require both the code and a case-insensitive message match, and test lookalike negatives such as a missing table, a missing statement, or a SqlError that echoes the text.

### 2026-11-26: Arrow results and metadata — Error wrappers must implement both Unwrap and Cause
**Context:** PR #587 added redactedCloudFetchError with only Unwrap(). A maintainer showed that pkgerrors.Cause(err)==io.ErrUnexpectedEOF went from true to false, even though errors.Is still worked. Adding Cause() fixed it.
**Rule:** When adding a new wrapper around an existing error, implement Cause() alongside Unwrap(), and add a regression test that checks both errors.Is and pkg/errors.Cause through the production wrapping chain.

### 2026-11-26: Configuration and authentication — Derive combined option state after all options apply
**Context:** In PR #587, WithTransport built HTTPClient inside the option itself, so ClientTimeout was captured or lost depending on option order. The fallback also handed out the shared http.DefaultClient. The fix builds the client in NewConnector after every option has run, copies DefaultClient before setting its timeout, and tests both option orders.
**Rule:** Build state that depends on several functional options in the constructor after all options have been applied, never inside one option, and test both option orders; copy global clients such as http.DefaultClient instead of mutating or sharing them.
